# B13: the docs read as one design (2026-10-26)

- `docs/architecture.md` is rewritten from the code on main: the walls,
  the four repos and their processes, a request's path, the log and its
  fold, provenance, the mailbox, messages, replies, the fetch rule, the
  shell, the daily note, files_move and undo, the calendar, and a table
  of I1 to I9 with where each is enforced and tested. Every mermaid block
  in it, `docs/messages.md` and `docs/house-shell.md` renders with
  mermaid-cli (one in house-shell.md did not: a semicolon in a note).
- `docs/house-shell.md` stays as the deep page for the shell, linked from
  the architecture page, rather than folded into it.
- `spec/relay.allium` passes `allium check` with no errors. Prose that the
  house phases wrote into `requires`, `ensures` and `when` clauses is now
  named black-box functions and triggers with the prose as comments;
  `Date` and `Fingerprint` are declared; rules and invariants named after
  notifying are renamed. Three warnings remain (Delivery's statuses and an
  unused WeekSpend), as at the baseline.
- README: `container system start` before `relay house build`; the
  upgrade paragraph names relay-tui and webtool and the service restart;
  a link to the architecture page; the secret-place list is
  `relay.shell/forbidden`, not the workbench's.
- `DEPLOY.md` holds Kira's deploy notes. `bb deploy` builds only
  agentloop and relay-tui. It does not start Apple's container service,
  build the steward's image, build webtool or restart relay serve; the
  notes cover those by hand, and the deploy code is unchanged.
- An old relay throws on any event kind it does not know, so a rollback
  after the new relay has written a message (nearly any tick) leaves a
  log the old relay cannot read. DEPLOY.md says so and lists the kinds.
