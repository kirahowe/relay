# B6: scouts

A house role's memo to a scout is now public as written, replacing B2's
interim refusal, and a scout's `egress` calls follow the fetch rule (O1,
I4). webtool refuses a moved target holding any Unicode space.

What was built:

- `relay.shown`: the pure rule (`addresses`, `refusal`) and relay's record
  of what the web showed a session. `tools/call!` runs every `egress` call
  through it. A `url` argument, and any `scheme://` address anywhere else
  in the call, must appear verbatim in an earlier `egress` result of the
  same session, or the call is refused before the tool runs, with fixed
  text that quotes nothing of it. Each `egress` result is kept as a file
  under `<data>/runs/<role>/<wake>/shown/` before it goes back to the
  model.
- relay.edn refuses an `egress` tool of an MCP server, since agentloop
  calls those itself and relay would never see the call.
- `memo/send` from a house role to a public role emits a public memo with
  the session's labels less private. The sender's tool result says it went
  out as written. A role whose own id was written in private is refused,
  since the scout would see its name. A scout's memo always carries
  contaminated. A scout may answer a role that sent it a memo it was shown.
- The grants summary and `resources/AGENTS.md` tell a scout to fetch only
  what it was shown, and a house role that a memo to a scout goes out as
  written.
- `bb staging init` gives the scout webtool's search and fetch (from
  `../webtool/bin/webtool`, with a `webtool.json` in the directory) and a
  public routine, `grant-search`, daily at 07:00: grants for the Harbour
  Sound Society, a made-up community choir, sent to the hub. The hub's
  text is public in that seed so the scout can reach it.
- webtool: `moved` refuses a target containing any rune for which
  `unicode.IsSpace` is true (U+00A0, U+3000, U+2003 and NEL tested). The
  README's relay.edn section now describes the house: search and fetch
  are `egress` tools for a scout, relay checks fetches, and there is no
  quarantine and no reader. The check section no longer says relay calls
  it.

Judgment calls:

- relay keeps its own record of `egress` results rather than reading
  agentloop's session store. relay sees each result before the model
  does, so the record is never behind; agentloop's store is another
  repo's format; and only `egress` results may count. The text of
  relay's own tools, a memo from the steward above all, must never make an
  address fetchable, and agentloop's store mixes every tool's results.
- "Same session" is a wake plus the wakes it resumes (`:resumes`). A
  conversation that loads another session within one wake shares that
  wake's record. That is wider than one agentloop session, but every
  address in it came from the web, so it carries nothing the steward
  wrote.
- The rule applies to every `egress` call, not only a tool named fetch:
  the whole `url` argument, plus any `scheme://` address in any other
  string, keys included. A search query with a made-up address is refused
  too, because webtool echoes a query back ("No results for ...") and the
  echo would otherwise make the address fetchable. A `url` must start with
  its scheme and hold no space, control or format character.
- An address is matched as a substring of the shown text, as the plan
  says ("appeared verbatim"). That lets the model pick a prefix of a shown
  URL. Picking one is a low-bandwidth covert channel, which the threat
  model leaves out.
- Only successful results are recorded. A refusal from webtool can quote
  a target it refused.
- Scenarios and evals make staging data without the scout's web and
  routine (`init!` `:scout-web?`), so no mock or live run reaches the real
  web unless a case grants it, and the fact ids scenarios rely on stay as
  they were.
- The pentest's S1 scenarios now expect the hub's memo to the scout to go
  as written, and the scout's attempt to post the canaries in an address
  it built to be refused before it runs. The scout's model may now see a
  canary the hub chose to send it, so that check is gone.

Not done here:

- The Brave key is not in this machine's keychain (`relay-brave`), so the
  staging scout's routine was not run live. Its settings were checked by
  running webtool against the staging `webtool.json`.
- Kira is still shown "[from outside]" for a scout's memo, not "from the
  web": the marker does not yet say where text came from.

Tests: `shown_test` (I4 as two properties over generated session
histories, plus examples), `scout_test` (through `tools/call!` with an
envelope stand-in: a made-up URL never reaches the tool, a resumed wake
keeps its record), `public_roles_e2e_test` (the same through the real
agentloop), `public_roles_test` and `house_test` (memos to and from a
scout), `labels_test` (the marker property now allows a house role's
memo to the scout to be public), `staging_test`, and webtool's
`TestMovedRefusesUnicodeSpaces`.

## Fix round 1

Two review findings, both fixed test-first.

- A query could make a made-up address fetchable. The inline check
  trimmed closing punctuation from a query's address, and webtool echoes
  a query as written ("No results for ..."), so a query of a shown
  address plus a tail of punctuation put the longer address in the
  record. webtool also escapes a newline or an invisible character in its
  echo as `\u{...}`, which joins two runs into one. An address in a
  string other than `url` now runs from its first scheme to the end of
  the string, untrimmed, and must be printable ASCII with no space, as
  well as shown. A query that quotes a shown address followed by
  anything, a full stop included, is refused with its own fixed text.
  `shown_test` has a property that an allowed query, echoed back the way
  webtool's search and ask do, makes no address fetchable that was not
  before, beyond the echo's own closing quote and full stop. It fails on
  the old trimming rule and on a rule without the ASCII check.
- An `egress` tool relay could not read. relay.edn accepted an `egress`
  tool run as a command given the model's arguments, and an envelope one
  with a parameter such as `host`, whose addresses relay never checks.
  `config/egress-problem` now requires an `egress` tool to be
  `:envelope` with its `:parameters` properties listed, each one `url`,
  a number or boolean, or a string named in the tool's new `:queries`
  key: free text the operator says goes only to a service trusted as the
  model provider is, such as the search query. `:queries` on any other
  class is refused. The staging, setup and example tools, the test
  fixtures and the pentest's `web_post` (now an envelope tool taking a
  `url`) follow.

Judgment call: the marker is a list of parameter names, `:queries`,
rather than a convention that a parameter called `query` is trusted, so
the operator states it for each tool. Recorded under decisions for Kira.
