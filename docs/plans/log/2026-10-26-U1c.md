# U1c: setup, config and the first hour

The self-hoster's papercuts from the U1 panel, fixed.

## The steward is the main role's name

The main role's id is now `steward`, everywhere: config defaults
(`:dead-letter-handler`, `:serve :websocket :default-role`), `relay
init`, `setup/steward.md` (was `setup/hub.md`), the example config, the
README, the staging seed and every eval scenario. The plan, the README's
house sections and the `:brief` refusal already said steward, and the
role is no longer only a hub that routes work: it reads the mailbox,
writes the daily note and holds the shell. Keeping `hub` would have left
two names for one thing in every doc a self-hoster reads.

The shared instructions (`resources/AGENTS.md`) say "the steward" in
prose, and each role's prompt names the steward's id from
`:dead-letter-handler`, so an install whose main role has another id,
such as Kira's `hub`, still tells its roles where to send things. The
README's Upgrading section says to set `:dead-letter-handler` (and
`:serve :websocket :default-role`) to the old id. Eval scenarios kept
their `:version`: only the role's name changed, and the prompt surface
digest records the change.

"Team member" and "helper" are gone from Kira-facing text: `relay
changes`, the revert refusals, help and `setup/steward.md` say role.

## relay init

`relay init` writes a complete `relay.edn`: everything relay can do is
there, commented out with placeholders (mail to you, the mailbox, GitHub,
the calendar feed, the shell and its grant, `:files`), and the daily
note is on. With webtool it writes the scout's tool and grant, and
`webtool.json` keeps snapshots in `<data>/webtool/snapshots`. After
writing it adds the steward (from `setup/steward.md`), its daily-note
skill and routine (`setup/daily-note/`, which staging now reads too, so
there is one copy), and with the web a scout from the new
`setup/scout.md`. It ends with three next steps, and runs each key
command to say whether it works, never showing what it printed.

Judgment call: init asks no new questions. It writes the sections
commented out rather than asking for addresses and folders, which keeps
the interview short and every answer reviewable in one file. With a
scout, the steward is added with public text (as staging does), so the
scout can see and answer it; `setup/steward.md` is public anyway.

## relay.edn

- An unknown top-level key is refused, with the closest known key
  (Levenshtein, at most a third of its letters) as "Did you mean". This
  reverses the old rule that ignored unknown keys so the tick would not
  stop; the tick still reports a broken relay.edn as an alert, and a
  silent typo cost the self-hoster their mail. `:chat-client` and
  `:verifier` get their own messages; grants refuse `:reports`,
  `:quarantine` and `:workbench` as removed; `:class :act` says what to do
  instead; `:format` must be 1 when present.
- A leading `~` in `:house :mounts` and `:files` is expanded at load.
- README: Upgrading lists every refused key with what to do.

## Failures told once, plainly

- A dead letter of the operator's own memo is told to her at once, in
  one message with `relay retry`. The steward still gets it, with a line
  saying she knows. A dead letter's memo now names its letter (`:about`
  on `memo/sent`), so a dead letter of a dead letter reaches her by the
  original request's subject, and not at all when the request was hers.
- webtool's "api_key_command failed" becomes one relay alert ("Web
  search isn't set up yet", with the keychain command), no outside
  label, and `relay status` shows the line. The role gets a fixed text
  telling it not to report it. A later call that works resolves it.
- A harness that will not start on this machine is told as a local
  problem, not the model service's, and does not promise to recover by
  itself. `harness/paused` records what it said, and status shows it.
- Alerts are resolved when their trouble ends (harness recovered, source
  polled, web work runs, tool works) and leave Ready.

## Running things now

`relay routine run [<role>] <name>` fires a routine as the tick would
(`:routine/run`, operator only) and wakes its role. `relay note` shows
the daily note as it would go out; `relay note now` makes today's and
sends it. `relay poll` says "now watching" on a repository's first poll.
`relay house remove` removes the container and relay's own image, and
`relay house status` lists the mounts.

## Left for others

U1b owns `relay wake`'s raw EDN output and `--public` on a public role's
wake note; U1d owns the dashboard's ready view (it only sees resolved
alerts leave as `gone`).

## Fix round 1

The review found that renaming hub to steward could change an existing
install without a word. An install whose main role is `hub` and whose
relay.edn leaves out `:dead-letter-handler` would send dead letters to
Kira, tell every role about a steward that is not there, and route a
phone session with no role to nobody. `config/role-name-problems` now
says so, with the likely fix ("Your main role looks like hub: set
:dead-letter-handler \"hub\""). `relay status` shows it, and the tick
sends one alert (`settings/misnamed`), which is resolved once the names
match. `relay init` writes `:dead-letter-handler "steward"` out, so a
later default cannot move an install. Kira's live relay.edn still needs
both keys set before deploy; that is hers to decide.

- relay.edn that is not EDN is refused with the reader's reason and
  "Check the section you last edited", not a stack trace. The tick keeps
  the `:messages` of the last relay.edn that loaded
  (`.messages-last-loaded.edn` in the data directory) and alerts through
  those when the file cannot be read at all.
- init's optional parts are blocks of lines inside sections that are on:
  mail to Kira inside `:channels` with its route inside `:routes`, each
  ingest source inside `:ingest {}`, the shell, and `:files`. Removing the
  `;;` from one block's lines turns that block on. A test turns each
  block on by itself, for every push choice, with and without the web,
  and checks that the result differs from the original only by the `;;`
  and that relay accepts it. The mail route names only `"mail"`, so it
  never points at a push channel init did not write.
- `relay house remove` keeping an image named in `:house :image` has a
  test, which kills mutant M2.
- The search-key alert no longer promises that the work carries on by
  itself. Nothing reruns a request, so each request of Kira's own that
  the failing session carried is named once, with "ask again once the
  key is in": in the first alert, or in a short one of its own when the
  tool is already broken. A role's request is left to the role.
- When agentloop does not start, the alert and status name the binary
  that ran and say it may be older than relay, with the fix. Judgment
  call: PATH still wins over the sibling build, since Kira's live
  install may rely on that order. The README now says PATH wins and
  that `:bin` settles which binary runs.
- An empty daily note no longer uses up the day. `relay note now`
  records nothing when there is nothing to say. A recorded note that was
  not sent (from the tick) does not stop `note now` from making the
  day's note again once the steward has written its parts.
  `digest/composed` folds `:sent`, and an older event without it counts
  as sent, as does a morning brief.
- The quiet-hours test in messages_test has a lone `clerk` role, so it
  now sets `:dead-letter-handler "clerk"`. Without that, the new alert
  correctly joined its batch.

The stalled gate run did not reproduce. Alone, `bb test` passed 993
tests in 2m06s, and after this round 1002 tests pass in 2m14s. The quiet stretch after calendar-serve-test is the serve
and serve-websocket tests, about 46 s together, made longer when other
streams run their suites at the same time.
