# U1a: the UX panel's blockers and safety findings

Phase U1a fixes the blockers and safety findings from the U1 panel. Each
item below names the finding it answers.

## What changed

- **Scout search broke after anything was ingested** (webtool and relay).
  relay now passes an envelope tool only the class labels `private` and
  `contaminated`. Source labels such as `ics:calendar` or `mail:x` stay
  inside relay. webtool keeps the two class labels and ignores any other,
  so a label it does not know no longer refuses the call. Property tests
  in both repos: webtool's `TestParseIgnoresUnknownLabels`, and relay's
  `envelope-labels-are-always-among-the-classes`.
- **An older agentloop on PATH won over the built one.** relay now looks for
  `../agentloop/bin/agentloop` before PATH. `relay init` writes the binary it
  found as an absolute `:bin`. When agentloop refuses a field or label
  relay sends, the run says the binary is too old and names the fix.
- **Revert and the daily note.** A flagged change or suggestion has one number
  in the note, and the same number works in replies, in the client and on
  the command line: `relay revert 1` (or `relay revert 1 <note>`). The log's
  own number is never shown. A change no note numbered gets a handle, `c<k>`,
  from `relay changes`. Adding or removing a helper is refused with a plain
  reason, and an undo is never undone. Each success line is built from the
  state after the change, so relay does not print a success it did not
  achieve. A reply that says only "revert" and "not" is done in code and
  answered once, on the channel it came through, with no memo to the role. A
  reply that says more still reaches the note's writer. The wording for an
  undone new skill now says the skill was removed.
- **A name defanged twice.** A dot already written as `[.]` is left alone, so
  defanging twice is the same as once, and the mail, the client and the
  command line read the same.
- **The agent's own mail.** The mailbox poll passes over mail from one of the
  agent's own addresses, or with a Message-ID that relay made at one of the
  agent's domains. Such mail is marked seen, so it does not come back. An
  address that is also the operator's is never counted as the agent's.
- **Calendar.** An all-day event is a DATE value end to end: `calendar_add`
  and `calendar_update` take `all_day`, the feed writes `VALUE=DATE`, and
  `relay ready` shows the days. The feed has its own token, an HMAC-SHA256 of
  a fixed text keyed with the listener's token. The listener's token no
  longer opens the feed, so the subscription URL holds no key to the
  conversations. `relay calendar url [--host <name>]` prints the URL to
  subscribe to.

## Judgment calls

- **The feed token changes whenever the listener's does.** A calendar app
  keeps its subscription URL, so existing subscribers must subscribe again
  after the listener's token changes.
- **The tailnet name comes from `tailscale status --json`**, with a five
  second limit. When that fails, `relay calendar url` prints a placeholder and
  says to pass `--host`.
- **A reply that only says "revert" and "not" sends no memo.** relay has done
  the work, and waking a model to say so cost a wake and a second answer.
- **Adding or removing a helper is never undone.** A removed helper's name is
  never used again, so taking it away could not itself be undone.
- **The too-old check reads agentloop's stderr** for an unknown field or
  label. Any other refusal is not called too old.
