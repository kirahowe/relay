# Px: cleanup before Kira tries the system

Phase Px ran in the workspace `.next/house-b5` on top of relay `main`
(`877fdba`). It did the seven items the phase brief named. The commits group them by
concern. Commits are not integrated; the orchestrator rebases and moves
`main`.

## What changed

1. **`bb deploy` builds what the house needs.** webtool is now a deployed
   sibling: `relay.deploy/repo-keys` and `builds` include it, so the deploy
   moves its checkout to `main` and runs `make build` like agentloop and
   relay-tui. When the live `relay.edn` has `:house`, a deploy step checks
   `container system status`. If the system is not running, the deploy says
   so and says how to start it (`container system start`), and does not
   start it. Otherwise it runs `relay house build` against the live data
   directory. A failed image build does not fail the deploy; the message
   gives the command to run later. The pure part is
   `relay.deploy/house-commands`. Rollback moves webtool back too, and a
   record from before webtool was deployed leaves its checkout alone.
   DEPLOY.md and the README deploy section describe the new flow. `bb
   deploy` was not run.

2. **A house role can write to a scout as itself.** A memo from a role
   whose id, title and instructions are private is public as written, the
   same as any house memo to a scout. The scout is shown the memo and the
   sender's id, so it can answer. It is shown nothing else of that role.
   I3 and its property tests are unchanged, and the public-roles tests now
   cover this case. DEPLOY.md no longer tells Kira to make hub public.

3. **Email to another host requires STARTTLS.** `smtp://host:587` is
   accepted, and curl runs with `--ssl-reqd`, so a server that will not
   start TLS delivers nothing. `smtps://` keeps TLS from the start.
   Unencrypted `smtp://` stays limited to localhost, 127.0.0.1 and `[::1]`.

4. **Undo display.** A partly undone move reads "N of M still moved (K put
   back)", with the files still moved listed first. "Left empty" names only
   folders that nothing has gone back into since. An undo removes a folder
   only when every move into it, in any call, is undone. The removal is
   named relative to the granted folder. A repeat undo that does nothing
   says "Nothing more went back from move N:". The client gets the reasons
   without that headline, so relay-tui does not print "Not undone." twice.
   A refusal caused by a later move names that move and says that undoing
   it first helps. The change stays inside the undo display and folder
   removal paths of `moves.clj`.

5. **Wording and config.** The recipient-removed alert no longer offers
   `relay retry` for a role that is gone. `relay status` gives one line
   when `:house` and a `:shell` grant are set and the image is missing.
   A misspelled key in a tool map gets a "Did you mean" hint, and
   `:daily-note :role` is checked like the other role names. `relay init`
   over an existing `relay.edn` with no roles prints the starter commands.
   `:github-login` on a GitHub source leaves the operator's own items out
   of pushes and the daily note. The "from" note under a memo is dropped only when the
   subject starts with relay's own words for its source, as
   `provenance/subject-prefix` gives them. The lookalike overflow line says
   "may not be what they look like".

6. **Emoji sequences survive sanitizing.** A zero-width joiner or variation
   selector inside an emoji sequence stays, so a family emoji arrives whole.
   Elsewhere they are still removed, including between letters. Idempotence
   and the no-hidden-characters property are kept.

7. **Eval graders.** `injection-rewrites-facts` now also fails a close that
   cites the page, with the foil "Closed per the page.". The concert case
   no longer reads a bare "no" as a negation, and "No problem, the email was
   sent." is in its must-match list. The grader changes were not rerun live,
   and BASELINES.md says so.

## Decisions taken

- Item 2 follows decision 6 as written. The scout learns the sender's id and
  nothing else of the role. Kira should confirm that an id alone is fine to
  show.
- Item 1 keeps a failed image build from failing the deploy. The code is in
  place either way, and `relay status` reports a missing image.
- Item 5 puts the image notice on the `relay status` lines, not in the
  alert channel.
- Item 4 keeps a folder while any move into it is undone, even when its
  file was taken out by hand.
