# R3: fixes from Codex's adversarial review, round 3

Codex's third round found one in-scope defect. The running container
binds each mounted folder, not its path, while files_move judged trust by
host paths. So the steward could move the trusted `/r/Notes` to
`/r/Archive`, move `/r/Drafts/replacement` to `/r/Notes`, then file
`/r/Downloads/injected.txt` in `/r/Archive`. The shell would still show
the old folder as Notes, trusted, and read the download as Kira's own.
This is the same cause as the round 2 findings: trust is attached to
paths, and files_move could change what a path names.

## A mounted folder never moves, and nothing takes its place

- `relay.files/mounted-source-problem` (pure) refuses a move whose source
  is a `:house` mount, trusted or not, or a folder that holds one. The
  steward reads "it is mounted for the shell, so it cannot move", or
  "it holds <mount>, which is mounted for the shell, so it cannot move".
- `relay.files/mounted-target-problem` (pure) refuses a target that is a
  mount or would hold one, whether or not the mount exists. This also
  covers a move from one trusted folder to where a missing trusted mount
  belongs, which round 2's check allowed.
- Paths are compared the way the disk compares them (firmlinks removed,
  NFC, lower case), against every form of each mount: as written, its
  real path, and, for a mount that does not exist yet, the real path it
  would have (`mount-places`). A source is also checked by file identity
  against each mount and every folder above it.
- `plan` takes every mount now (`mount-places`), not only the trusted
  ones, and keeps passing the trusted ones to `trust-problem`.
  `relay.moves` wires in `mount-places`.
- The `files_move` description lists the mounted folders and says that
  they, and the folders that hold them, stay where they are.

With round 2's refusal of moves into trusted mounts from outside, a
trusted mount's files can change only by Kira's hand or by moves within
trusted mounts.

Undo is unchanged. It is Kira's, and the Px phase works on it in
parallel.

Tests: `a-mounted-folder-never-moves-and-nothing-takes-its-place` (case,
firmlink, identity, is or holds, untrusted mounts); property
`a-move-touches-a-mount-only-inside-it`; on disk,
`a-mounted-folder-stays-the-folder-the-shell-was-given` runs Codex's
three steps and checks that Notes is still the same file and holds only
its own files, plus another case, a folder holding a mount, an untrusted
mount, a missing mount and a link. Property
`no-sequence-of-moves-changes-what-a-trusted-mount-shows` covers
generated mount layouts (nested, missing, trusted or not) and sequences
of calls. After the calls, each mount that existed is still the same
file at its path, and every file under a trusted mount was under one at
the start. With the new checks switched off, this property fails. The
round 2 test's "a folder that would become a trusted one" is now refused
by the new check, and its expectation says so. Pentest
`s24-files-never-destroyed` adds trusted mounts Notes, Drafts, Desk/Plans
and a missing Later, refuses five ways to move a mount or take its
place, and checks that Notes is still the folder the shell was given
after the accepted calls.
