# U1e: the remaining U1 papercuts

## Moves and undo

- `relay undo <move>` puts back each move of a call on its own. A file
  changed since, moved again, or with something new in its old place
  stays where it is, and undo names it relative to the granted folder,
  with why and what to do next. The rest go back. When nothing can go
  back, nothing changes. `relay undo <move> <file>...` puts back only
  the files named, as `relay moves` shows them, and an unknown file or
  option is refused. The client's `u` runs the same code, and the
  dashboard shows the files left behind.
- Undo removes the empty folders made for the moves now back: by this
  call, or by another call when a file this undo put back was in it. It
  keeps a folder that a later call, not yet undone, moved something out
  of, so that undo can still put it back. Each folder removed, or kept
  because something new is in it, is recorded on the call that made it,
  and no later undo touches it again (fix round 1: an unrelated undo
  used to sweep Kira's empty folders).
- A step whose target or old place a later call, not undone, has moved
  from or onto is left with "Move N has moved x since. relay undo N
  first". Found by the I7 property at 1200 and 2000 trials: a file moved
  away and back by later calls looked unchanged, and undoing the first
  call early took it, or filled a place a later undo needed.
- Each refusal says what to do: an edited file names where it came from,
  so Kira can move it back herself and keep her edits. A file she moved
  back by hand counts as put back (`by-hand` in files/undone) and is not
  moved; the thing at the old place must be the same kind, and no move
  not undone may have put anything there.
  The I7 property now also undoes random moves of a call early, before
  the rest, and still ends with the tree byte for byte; it runs 200
  trials, and example tests pin both folder guards.
- `files/moved` records the folders a call left empty. relay never
  removes them; the role is told in the tool result, and `relay moves`,
  `relay ready` and the dashboard show "Left empty: old stuff".
- The role that made a move gets a memo from relay when the operator
  undoes it, with what went back in full paths.
- `files_moves`, a read tool for a role granted `:files`, lists its own
  calls with what was put back.

## The daily note

- "not N" says no to an item's offer and keeps the item: later notes
  show it without the offer, and `daily_note_draft` tells the writer.
  "drop N" (also "dismiss", "skip", "remove") removes the item for good.
  "not N" on an item with no offer changes nothing: relay answers that
  the item has no offer and that "drop N" removes it, so a casual no never
  hides a later reminder with the same key. `relay decline` and
  `_relay/messages/act` with op `decline` do the same; a dropped item can
  still follow a no.
- An item's text and offer are joined with a full stop when the text has
  none ("11:00. Want prep notes?").
- `offer_outcome` lets the note's writer record what came of an offer,
  by the item's key. `daily_note_draft` shows the outcomes, and the skill
  says to write where it stands in place of the offer, and to list every
  event of the next two weeks.
- A change undone, or a suggestion dropped or declined, reads as done in
  every note that numbers it, whichever note or command did it. Those
  notes' revs move, so a client is sent them again.
- `relay ready <n>` and the dashboard show a note's section headings.
  The wire sends `sections` beside the flat `lines`, which acts index.

## Calendar wording

resources/AGENTS.md and the steward's starter text say the agent's
calendar holds what the agent adds and never copies of the operator's
own events, and to say "my calendar" or "the calendar you subscribe to".

## relay-tui

Number keys on a note in the list open it at that item. `n` says no to an
offer. The help says `1-9`. A refusal, or the files an undo left, takes
up to a third of the screen. An open note keeps its headings, and a done
mark is shown once. core/ready.go and render/ready.go have their
open-item parts in ready_detail.go (moved, not changed).

## Judgment calls

- The undo memo wakes the role, which costs a model call per undo. The
  task asked for a memo; a quieter path (a note in the next wake's
  prompt) is an option for Kira.
- Outcomes of offers are shown to the writer, not put in the note by
  code: the writer may make a new offer for the same thing.
- "skip" and "remove" drop, like "drop" and "dismiss"; only "not" and
  "no" decline.
