# U1b: provenance that means something, and the words Kira reads

Provenance is now split in two. Labels still carry everything a session
may have seen, on every event, and still drive I3 and the breaking of
links. A second record, the sources (`relay.provenance`), says what
outside text the session read directly in its wake: the memos the wake
was for, and every result relay's tool command handed back, each counted
by its own recorded sources. relay keeps one file per result under
`runs/<role>/<wake>/read/`. An outside tool's page is recorded as
`web:<page or url>` and a search as `search:web`. The shell adds no
source, and neither does a refusal of relay's own. MCP tools run inside
agentloop, so any of their static labels the session holds counts. What
the prompt only showed (notes, skills, journal tail, fact topics, board)
does not count. Events written by a tool call carry `:sources`, and the
state keeps them by seq. An event with no sources recorded counts what
its labels name, so every old log folds as before.

Messages, prepared items, moves, cards, calendar entries and recipe
changes all read their sources this way. The daily note flags a change
by its sources, names where it came from ("shaped by the web page
office-holidays.html") and quotes a line of what it now says. A change
made in a wake that read nothing from outside is quiet, and that
includes one the operator asked for. A routine run carries the sources
of the routine, not of whatever its writer had in context.

Presentation: no subject or line is stamped. A role's message ends with
one line, "Drew on: ...". relay's own alerts, the daily note and the
operator's own threads carry none. Refs read as words. A link relay
builds itself (a GitHub item's) stays live. Mail carries a `:from-name`,
says "Reply to this mail to answer" when relay reads the mailbox, threads
with `Re:` only to a message that was mailed, and otherwise opens with
what it answers. defang now breaks only links and hosts.

With a daily note configured, GitHub items from people and failing
ingest sources go into the note rather than out at once. The note
always has its sections.

CLI: short `relay help` (`relay help all` for the rest), plain `relay
wake` sentences (refusals on stderr, exit 1), `relay poll` exits 1 when
a source fails, status guidance on an empty relay, memos indented under
their role with where they came from last, `relay reply` says it is
waiting, `relay log --json` is the stored event exactly, and `relay
week` uses words instead of internal kinds.

Judgment calls:

- The source of a tool's page comes from its `url` or `page` argument,
  and a call with `query` reads as a web search. That covers webtool and
  the staging stand-ins. Other outside tools read as "something from
  outside".
- A scout's memo always carries `search:web`, so the steward's footer
  says it drew on a web search even when the scout only fetched.
- "What I learned" stays the writer's to describe. relay does not list
  quiet changes there itself, as B10 decided.
- Ingest failures and GitHub news skip the note's push only when
  `:daily-note` is set. Without a note they still go out, GitHub news
  now at low urgency.

## Fix round 1

- Defang no longer trusts a list of top-level domains. Any dotted name
  with a label of two or more letters after the first, or a punycode
  label, is broken when a path, query, fragment or port follows it,
  whatever its ending. With nothing after it, a name stays whole only
  as a file name: one dot and a file extension (todo.md, setup.sh), or
  any number of dots when the extension is no top-level domain
  (jquery.min.js). So a bare `evil.rs` or `evil.sh` stays as written:
  it carries nothing in its labels, and `evil.sh/x` is broken.
- Mail and push take hidden characters out before defanging, never
  after, and so does the "Drew on" footer.
- MCP tools in relay.edn are found by `:protocol`, so their labels count
  as sources.
- A card keeps the sources of every event that wrote it.
- Kira's reply records no sources, whatever the message drew on.
- A wake takes memos with no outside source on their own when any are
  waiting; mailbox, GitHub and calendar memos wait for the next wake.
- `:daily-note {:grants "owner/name"}` names the grant search routine.
  relay records a `tool/failed` event on the wake when the web search key
  fails, and the Grants line says whether the search ran. Without
  `:grants`, the empty line reads "Nothing on grants since the last
  note."
