# B5: the agent's calendar

Added `calendar`, `calendar_add`, `calendar_update` and
`calendar_remove` (the last three class `edit`, all for roles that are
not public). Events live in the log as `calendar/added`,
`calendar/changed` and `calendar/removed`, versioned the way facts are:
each change is a new version with its labels, and removal keeps the
history. `relay.ics` renders the feed as pure code. `relay serve`
answers `GET /calendar.ics` on the WebSocket listener it already has.

Judgment calls:

- Only roles write the calendar. The operator and the dispatcher are
  refused, so I9 holds by construction: the feed is exactly what roles
  wrote. Kira corrects an event by asking a role.
- Removed events stay in the feed as `STATUS:CANCELLED` for 30 days,
  then drop. Dropping at once would leave a subscribing app with an event
  that never goes away. Keeping them forever would grow the feed. 30 days
  is longer than any sane polling gap.
- The feed takes the listener's token as a bearer token or as
  `?token=` in the URL. Calendar apps cannot send a header. The URL
  form is tailnet-only and the token is the one the phone client
  already uses. Kira may want a separate, feed-only token (see the
  report's decisions).
- UIDs are `relay-event-<id>@relay.invalid`. Nothing in the core may
  assume Kira's domain, and `.invalid` can never collide with a real one.
- No disclosure: the calendar name is "Agenda", and nothing in the feed
  says an agent wrote it.
- An update that moves the start to or past the old end is refused
  with a plain reason. The role then gives the end too, instead of relay
  guessing a duration.
- At most 1000 live events, so a runaway session cannot fill the feed.
- Text is cleaned with `relay.text/hidden?` before escaping, so bidi and
  invisible characters cannot hide anything in a title.

Tests: `ics_test` (round trip through a parser written in the test,
folding at 75 octets on UTF-8 boundaries, escaping, UTC, UIDs, ordering,
cancellation window, injection), `calendar_test` (versioning, SEQUENCE,
who may write, validation, tools, labels, a property over random
histories) and `calendar_serve_test` (the routing as a property, and the
service end to end).

this workspace before the commits. The full `bb verify` was not run here.
